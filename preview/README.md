# Mobile interaction preview

Run `npm run ui:preview` with the project's Node 20 runtime. Open
http://127.0.0.1:4188. The server binds to loopback only.

This is a development fixture for the actual shared React Native components,
rendered through React Native Web. It does not import auth, SQLite, sync or API
clients. Its actions change fixture state only. It is not the installer app or
an end-to-end acceptance test. No preview route is added to the Android app.

The Vite configuration resolves Expo's `.web` implementations and its JSX/Flow
dependencies. It does not change Metro or the native build configuration.

## September 26 verification

- Disabled/busy actions do not execute; cancelled presses do not execute.
- Reduced-motion preference is observed through one app-wide subscription.
- Confirmation backdrop and Android back cannot dismiss an in-flight operation.
- Existing custom styles, transforms, native refs and Expo Link targets preserved.
- Cyrillic headings use Manrope instead of missing Sora glyphs; Hebrew uses the
  native system sans-serif family with explicit weight.
- Shared components checked in EN/RU/HE, including RTL, at measured browser CSS

- Fixture workflow: open position, confirm completion, see updated count and

Automated checks: `npm run test`, `npm run typecheck`, and
`npm run test:coverage-contract`. Component tests mock native primitives;
native-device performance, gestures and screen-reader focus remain device checks.
Final run: 423 tests across 33 files, including 19 UI/workflow tests. The mobile

Remove that temporary output after verification. No APK is generated by the UI preview.

## September 27 project execution screen

Open `/project.html` on the same preview server to render the actual
`app/project/[id].tsx` screen with isolated in-memory fixtures. The fixture controls
can reset work or fail the next local save. Language selection covers EN/RU/HE.
Navigation destinations are displayed instead of opening real account screens.
All service aliases live only in this Vite configuration; Expo/Metro is unchanged.
This validates layout and UI feedback, not native SQLite, network sync or device behavior.

Verified on the actual screen at measured CSS widths of 322 and 393 px:
door selection scroll, inline save failure and retry, installed and not-installed
results, add-on submission, readable action buttons and loaded door image.
RU, EN and Hebrew RTL were checked without horizontal overflow.

The execution pass adds same-frame submission locking, focus/background-sync
refresh, and inline acknowledgements that distinguish a committed local save from
a failed view reload. Server detail hydration rechecks pending/failed work inside
the workspace database queue; door and add-on writes use that same existing queue.
Public APIs, database schema, pay calculation and server acceptance remain unchanged.

Automated coverage includes 10 actual-screen tests, 6 field-write serialization
tests and 4 additional project refresh cases. Full run: 443 tests in 35 files.
The mobile quality gate and Android export passed. No APK was installed and no
phone was attached; device/offline acceptance is still required.

## September 27 calendar workflow

Open `/calendar.html` for the actual mobile calendar with isolated visit fixtures.
The Online, Cached and No data switches exercise display states only. Add
`?day=2026-08-31` to check the earnings-to-calendar date link. Event titles are
English fixture content; UI controls follow EN/RU/HE. Waze intentionally returns
a test error instead of opening an external app. Navigation displays the target
route, not a real account screen. Nothing is written to the backend or SQLite.

Verified at browser CSS widths of 322 and 393 px: visit details above the calendar,
long-description scrolling on a short viewport, dismissal, readable controls,
Hebrew modal direction and chronological time range, offline/unavailable states,
and routes to assigned doors, project issues and the selected day's earnings.
The page did not horizontally overflow. Native gestures, screen-reader focus and
the actual external-app launch still require a device check.

The screen now groups dates in the same local timezone used to display times,
retains incoming date selection, uses the API's actual visit types and refreshes
on focus/background sync. Account changes hide the old plan immediately. Stale
screen responses are ignored, and a late response cannot overwrite a newer saved
offline snapshot. A visit title is no longer treated as a door identifier: the
backend contract has no door-to-visit association.

Full run: 488 tests in 37 files, including 16 actual-calendar-screen tests and
date, navigation and cache regression coverage. `npm run quality-gate` and the
Android export passed. The temporary `.tmp/calendar-workflow-bundle` output
(4.71 MiB) was removed. No APK was installed; no phone acceptance was performed.
No backend schema, assignment, payroll or public API contract was changed.
